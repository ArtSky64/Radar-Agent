# AI Радар и Scout: Автономная система мониторинга AI/ML

Автономная платформа мониторинга, семантической дедупликации и интерактивной аналитики релизов в сфере искусственного интеллекта, машинного обучения и нейросетевых технологий.

Платформа агрегирует данные из первоисточников:
* Hugging Face — мировые и русскоязычные трендовые модели и датасеты;
* ArXiv и Papers with Code — актуальные научные публикации и препринты;
* GitHub Trending — трендовые AI-репозитории, инференс-движки и открытые библиотеки;
* LMSYS Chatbot Arena — регулярные замеры рейтинга Elo и лидерборд языковых моделей.

Семантическое отсечение дубликатов выполняется локально через FastEmbed (модель paraphrase-multilingual-MiniLM-L12-v2, 384-мерные векторы, косинусный порог сходства 0.59). Веб-интерфейс оснащен диалоговым RAG-ассистентом с сохранением контекста беседы.

---

## Возможности системы

1. Диалоговый RAG-ассистент с удержанием контекста:
   * Память диалога: агент помнит контекст беседы внутри активной вкладки, корректно отвечает на мета-вопросы (например, «А что мы обсуждали ранее?») и помогает глубже исследовать выбранный материал.
   * Управление сессиями: кнопка создания нового диалога очищает контекст и позволяет начать исследование с чистого листа.
   * Форматирование ответов: полноценная поддержка разметки Markdown, блоков кода с подсветкой синтаксиса и кликабельных ссылок на первоисточники.
   * Регулировка источников: слайдер выбора количества источников в ответе позволяет гибко настраивать глубину контекста базы знаний.
   * Отказоустойчивость: при отсутствии подключения к внешнему серверу LLM (vLLM/Qwen) ассистент автоматически переключается в локальный векторный режим и продолжает находить релевантные карточки.

2. Мониторинг ключевых источников:
   * Каталог разбит на разделы: Лидерборд Arena, Трендовые модели HF, Модели HF (RU), Статьи (Papers), Датасеты, Репозитории GitHub, ИИ-Рекомендации (RAG).
   * Быстрый поиск по всем материалам через палитру команд (сочетание клавиш Ctrl + K).
   * Автоматическое извлечение характеристик: параметры моделей (7B, 27B, 70B), задачи, направления, теги, лицензии, метрики загрузок и звезд.

3. Векторная дедупликация и индексирование:
   * Локальное построение эмбеддингов (384 измерения) без расхода квот внешних API.
   * Индексация и KNN-поиск через библиотеку sqlite-vec с поддержкой сохранения на диск.
   * Дисковое кэширование эмбеддингов для исключения повторных вычислений.

## Быстрый старт через Docker

Проект полностью упакован для запуска через Docker Compose с multi-stage сборкой интерфейса и бэкенда.

1. Переход в папку проекта:
```bash
cd agent
```

2. Настройка файла переменных окружения:
```bash
cp .env.example .env
```
При необходимости отредактируйте параметры в файле `.env` (для базовой работы и локального RAG внешние ключи не требуются).

3. Сборка и запуск контейнера в фоновом режиме:
```bash
docker compose up --build -d
```

Сервисы будут доступны по адресам:
* Веб-интерфейс и API: http://localhost:8000
* Интерактивная документация Swagger: http://localhost:8000/docs

Остановка контейнера:
```bash
docker compose down
```

## Локальный запуск без Docker

### 1. Подготовка виртуального окружения Python

Требуется Python версии 3.10 или выше.

```bash
python -m venv venv

# Активация окружения в Windows (PowerShell):
.\venv\Scripts\Activate.ps1

# Активация окружения в Linux / macOS:
source venv/bin/activate

pip install -r requirements.txt
playwright install chromium
```

### 2. Сборка статики фронтенда

Требуется Node.js 18+.

```bash
cd web
npm install
npm run build
cd ..
```

После выполнения команды в папке `web/dist` будет создана оптимизированная сборка фронтенда, которую FastAPI раздает автоматически.

### 3. Запуск через All-in-One менеджер (run_all.py)

Скрипт `run_all.py` позволяет управлять всеми процессами платформы из одной консоли:

```bash
# Базовый запуск: поднимает FastAPI сервер со встроенной раздачей веб-интерфейса
python run_all.py

# Запуск только веб-сервера без фонового пайплайна сбора:
python run_all.py --no-pipeline

# Разовый прогон сбора данных при старте:
python run_all.py --run-once

# Запуск режима горячей разработки фронтенда (Vite dev server на порту 5173):
python run_all.py --dev-web
```

Приложение доступно в браузере по адресу: http://localhost:8000.

### 4. Ручной запуск компонентов по отдельности

Если требуется запустить компоненты изолированно:

Запуск бэкенда с раздачей интерфейса:
```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

Запуск режима активной разработки фронтенда с Hot Module Replacement (HMR):
```bash
cd web
npm run dev
# Открывается на http://localhost:5173 (проксирует API-запросы на порт 8000)
```

## Запуск сбора данных через CLI (main.py)

Скрипт `main.py` осуществляет сбор, дедупликацию, ИИ-анализ и запись данных в базу SQLite:

```bash
# Полный цикл сбора по всем источникам (GitHub, HF Models, Arena, Datasets, Papers):
python main.py

# Сбор только научных статей:
python main.py --only-papers

# Сбор только датасетов (Hugging Face + Kaggle):
python main.py --only-datasets

# Сбор только трендовых репозиториев GitHub:
python main.py --only-github

# Сбор только трендовых моделей Hugging Face:
python main.py --only-models

# Сбор только данных лидерборда LMSYS Arena:
python main.py --only-arena
```

Для периодического автообновления данных по расписанию используется фоновый планировщик:
```bash
python scheduler.py
```
Периодичность настраивается через переменную `PIPELINE_INTERVAL_HOURS` в `.env` (по умолчанию 72 часа).

## Конфигурация (.env)

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `VLLM_BASE_URL` | `http://127.0.0.1:2233/v1` | Базовый URL OpenAI-совместимого API инференса (vLLM / Ollama / OpenAI) |
| `VLLM_MODEL_NAME` | `Qwen/Qwen3.6-27B` | Наименование рабочей генеративной модели |
| `VLLM_API_KEY` | `not-needed` | Ключ авторизации для LLM-сервера |
| `DB_NAME` | `data/app_database.db` | Путь к файлу базы данных SQLite |
| `DUPLICATE_THRESHOLD` | `0.59` | Косинусный порог отсечения смысловых дубликатов |
| `VECTOR_DIM` | `384` | Размерность векторов FastEmbed |
| `LOG_LEVEL` | `INFO` | Уровень логирования событий |
| `LOG_FILE` | `data/app.log` | Путь к основному файлу журнала |
| `ERROR_LOG_FILE` | `data/errors.log` | Путь к журналу ошибок анализа |
| `GITHUB_TOKEN` | — | Персональный токен GitHub для повышенных лимитов API |
| `HUGGINGFACE_API_KEY` | — | Токен Hugging Face для доступа к карточкам моделей |
| `KAGGLE_USERNAME` | — | Имя пользователя для Kaggle API |
| `KAGGLE_KEY` | — | Ключ доступа Kaggle API |
| `PIPELINE_INTERVAL_HOURS` | `72` | Интервал повторного сбора в scheduler.py |

## Тестирование

Запуск полного набора автоматических тестов:

```bash
# В среде Windows (PowerShell):
$env:PYTHONPATH="."
.\venv\Scripts\pytest.exe

# В среде Linux / macOS:
PYTHONPATH=. pytest
```

Набор тестов включает:
* `tests/test_dedup.py` — проверка косинусного сходства, порогов дедупликации и работы sqlite-vec;
* `tests/test_kaggle_fetcher.py` — проверка парсинга тегов, метрик и схемы выборки датасетов;
* `tests/test_leaderboard_view.py` — проверка преобразования и агрегации лидерборда моделей;
* `tests/test_rag_agent_context.py` — тестирование сохранения контекста диалога и изоляции сессий;
* `tests/test_rag_service_sqlite_vec.py` — тестирование сквозного векторного поиска и KNN-индекса.
